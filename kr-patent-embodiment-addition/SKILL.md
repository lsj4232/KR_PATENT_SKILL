# 변형 실시예 추가

기본 실시예와 비교해 기술적으로 의미 있고 근거 있는 변형을 보완한다. 변형의 수나 최신 기술 키워드가 목표가 아니다.

## 후보 선택

발명자료와 기존 본문에서 대안적 구성·처리·재료·배치·입출력·조건을 찾는다. SW에서는 알고리즘, 모델, 사용자 개입, 배포, 장애 대응 등이, HW에서는 결합 방식, 형상, 재료, 작동 조건 등이 후보가 될 수 있다. 해당 발명에 관계없는 블록체인·AR/VR·다국어 목록을 자동 추가하지 않는다.

후보마다 **기본안과의 차이 / 작동 방식 / 기대 효과의 근거 / 청구항과의 관계 / 원자료 위치**를 기록한다. 서로 양립하지 않는 변형을 동시에 필수인 구성처럼 쓰지 않는다. 모든 변형이 현재 청구항에 포함된다고 단정하지 않는다.

## 본문 반영

- 확인된 변형은 관련 기본 실시예 뒤에 설명한다. 문체와 길이는 이해에 필요한 만큼으로 정한다.
- 브레인스토밍 요청에는 미확인 아이디어를 후보로 제공할 수 있으나 확인된 발명 내용·실험 결과처럼 본문에 섞지 않는다.
- 출원 후에는 최초 명세서·도면에서 근거를 확인한다. 그 근거가 없는 변형은 삽입하지 않는다.
- 본문 보완만 요청하면 청구범위는 보존한다. 청구항 추가까지 요청받으면 별도 변경으로 구분하여 `kr-patent-dependent-claim-drafting`으로 연결한다. 사용자 요청 자체를 일률 거부하지 않는다.

완료 시 추가 문단·위치·근거와 미확인 후보를 제공하고, 본문·도면·청구항의 모순 및 원치 않은 청구항 변경을 확인한다. 변형 추가만으로 향후 보정·분할출원 가능성이나 권리 확대를 보증하지 않는다.
