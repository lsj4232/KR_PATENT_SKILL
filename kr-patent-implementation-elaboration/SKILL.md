# 구성요소·처리 흐름 구체화

추상적인 기능 설명을 실제로 이해 가능한 동작 설명으로 보완한다. 이미 충분한 부분은 다시 늘리지 않는다. 정의 삽입 스킬을 사전에 반드시 실행할 필요는 없다.

## 구성요소 단위

자료에서 해당 구성의 입력, 판단 기준, 적용 방법, 출력·효과를 찾는다. 예를 들어 '검증한다'만 있으면 무엇을 무엇과 대조하고 어떤 결과가 다음 처리에 전달되는지 설명한다. 자료에 기준이 없으면 가능한 후보를 질문용으로 제시하며 확정 본문에 넣지 않는다.

## 전체 흐름

구성 사이의 데이터 이동·변환을 이어 설명한다. 식별자나 출처 상태 플래그가 실제 사용될 때에는 그 생성·승계·이용 지점을 밝혀 추적 가능하게 한다. 모든 발명에 provenance flag, 식별자 또는 폐루프를 새로 추가하지 않는다. HW는 물리적 연결과 작동 관계로 설명한다.

## 편집·검증

- 문단은 관련 구성이나 흐름 설명 옆에 삽입한다. 내부 작성 마커는 결과 본문에서 제거한다.
- 고정된 3개 기준, 4개 요소, 문장 수나 일률적인 종결어미를 요구하지 않는다.
- 청구항·원자료·도면부호와 대조하고 원치 않은 청구항 변경이 없는지 확인한다.
- 출원 후에는 모든 보완 내용의 최초 명세서·도면 근거를 확인한다. 부족하면 질문 또는 검토안으로 분리한다.

추가 문단, 삽입 위치, 근거, 해결되지 않은 질문을 제공한다. 효과 수치·실험 결과를 만들어 설명의 빈칸을 채우지 않는다.
