# 한국 특허 작성 워크플로우

요청한 범위에서 기존 산출물을 이어 사용한다. 모든 스킬을 처음부터 읽거나 모든 단계를 실행하지 않는다. 아래 Stage 번호는 기존 호출과의 호환을 위해 유지한다.

## 시작과 진행

- 입력의 정본·버전, 출원 전/후 상태, 청구항 수정 범위, 최종 산출 형식을 확인한다. 이미 주어진 답은 다시 묻지 않는다.
- 자료가 충분하면 계획을 짧게 알리고 진행한다. 권리범위를 바꾸는 미정 선택이나 근거 부족만 질문하고, 그 답과 무관한 작업은 계속한다. 사용자가 단계별 검토를 요청한 경우에는 그 방식을 따른다.
- G(AI·SW·제어), H(기계·전기전자·화학), 혼합은 참고자료 선택용 분류다. 청구항 카테고리를 분야만으로 강제하지 않는다.
- 요청한 산출물에 필요한 단계만 진행 상태로 추적한다. 완료·진행·확인 필요·해당 없음을 구분한다.

## 단계 선택

| Stage | 필요한 작업 | 사용할 스킬 | 완료 기준 |
|---|---|---|---|
| 0 | 현재 자료 진단 | 직접 진단; 별도 진단 보고서 요청 시 `kr-patent-stage-recommender` | 정본, 누락 자료, 작업 범위 식별 |
| 1 | 기술 내용 확인 | `kr-patent-inventor-meeting` | 작성에 필요한 미확인 사실과 질문 정리 |
| 2 | 청구항 작성·확인 | `kr-patent-claim1-drafting`, 필요 시 `kr-patent-dependent-claim-drafting` | 초안, 근거표, 인용관계 확보 |
| 3 | 도면·부호 준비 | `kr-patent-symbol-design`; 실제 도면 매핑은 `kr-patent-drawing-mapping` | 객체·부호·명칭의 일관된 대응 |
| 4 | 본문 구성 설계 | `kr-patent-spec-drafting` | 과제·구성·효과와 청구항 근거 연결 |
| 5 | 본문 작성 | `kr-patent-spec-drafting` | 요청 범위의 본문 초안과 미확인 사항 |
| 6 | 모호한 용어 정의 | 필요할 때 `kr-patent-definition-insertion` | 용어 의미와 범위가 문맥상 명확 |
| 6.5 | 구현 설명 보완 | 필요할 때 `kr-patent-implementation-elaboration` | 처리 기준·입출력·구성 관계가 설명됨 |
| 7 | 변형 실시예 보완 | 필요할 때 `kr-patent-embodiment-addition` | 근거 있는 변형과 미확인 후보 구분 |
| 8 | 전체 정합성 검토 | `kr-patent-consistency-check`; 반복 수정 요청 시 `kr-patent-ralph-loop` | 근거가 있는 결함·미검증 범위 정리 |
| 9 | 수정·재검증 | 결함에 해당하는 스킬 또는 직접 수정 | 허용된 수정 반영, 영향 구간 재검증 |
| 10 | 파일 출력 | `kr-patent-docx-builder` | 파일 생성, 내용·구조 검증 |
| 11 | 스킬 개선 | 요청된 경우에만 `kr-patent-skill-updater` | 근거 있는 지침 수정과 검증 |

청구항이 없더라도 작성 요청과 기술 근거가 있으면 Stage 2에서 초안을 작성한다. 기존 청구항은 사용자가 허용한 범위에서만 수정한다. 도면이 없으면 도면 설계안과 확보된 내용의 초안을 진행하고, 존재하지 않는 도면을 본문에서 확정 인용하지 않는다.

Stage 6~7은 자동 분량 늘리기 단계가 아니다. 정의나 실시예가 충분하면 건너뛴다. 문체 표지가 없다는 이유만으로 미완료로 판정하지 않는다.

## 조건부 도구와 인계

- 새 블록도는 `patent-block-diagram`, 기존 PBD 수정은 `patent-block-diagram-refine`, PNG 부호 삽입은 `kr-patent-drawing-tagging`을 필요한 경우만 사용한다.
- 기존 DOCX의 서식·탐색창만 고치면 각각 `kr-patent-format-unify`, `kr-patent-navigation-pane`으로 처리한다. 텍스트로 재빌드하여 사용자 편집을 잃지 않게 한다.
- HLZ는 요청된 경우에만 `docx-to-hlz`로 변환한다. 변환과 전자출원 제출은 별개다.
- 다음 단계에 정본 파일, 청구항·용어·부호표, 확정된 선택, 근거 위치, 미확인 사항을 전달한다. 이전 스킬 전체를 다시 로드하지 않는다.
- 다른 스킬은 설치·접근 가능한지 확인한 후 사용한다. 없으면 명시하고 현재 가능한 범위의 결과를 제공한다. `/full`은 별도 등록 없이는 보장되는 명령어가 아니므로 자연어 또는 실제 환경의 스킬 호출 방식을 쓴다.

## 마무리

산출물 링크, 완료 범위, 남은 실질 결함과 미확인 사항을 전달한다. 출원 후 작업은 최초 명세서·도면에 대한 변경 근거도 확인한다. 청구항 불변만으로 신규사항 검토를 대신하거나 출원 적합성을 보증하지 않는다.
