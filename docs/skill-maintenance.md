# 스킬 정리 기준과 근거

2026-11-04 검토. 기존 24개 스킬 이름과 도구 경로를 유지하면서 호출 설명, 핵심 작성·검토 워크플로우, 참고자료의 중복·강제를 줄였다.

## 주요 판단

- 독립항 645자, 종속항 3줄, 실시예 600문장 등의 수치를 기본 강제에서 제외했다. 사용자가 지정한 작성 제약은 따르되 기술적 근거를 삭제하거나 만들어 맞추지 않는다.
- 과거 '70점 → 100점', 모델별 고정 비용, 심사관 심리 단정은 재현 근거나 적용 범위를 확인할 수 없어 핵심 지침에서 제거했다.
- '항마다 승인', '모든 보강 단계 수행', '작업 종료 시 자동 회고'를 기본 경로에서 제거했다. 실제 권리범위 선택과 미확인 사실은 계속 구분한다.
- 청구항 미보유 상태에서 전체 워크플로우가 멈추던 경로를 기존 청구항 작성 스킬로 연결했다.
- 반복 정제는 결함 ID·해결 여부·정체·회차 상한으로 끝낸다. 손상 시 회차 전체를 복구하며 단순 청구항 복구 뒤 계속하지 않는다.
- 누적 학습 도구는 섹션 수준·코드 펜스·중복·백업을 검증한다. 도구는 호환용이며 기본 개선 방식은 기존 규칙 수정·통합이다.
- DOCX 설명을 실제 빌더에 맞췄다. 폰트·크기·layout·청구항 헤더와 도면 이미지 미지원 사실을 명시했다.

## 기술 검증과 법적 판단 구분

[특허법 제42조](https://www.law.go.kr/법령/특허법/제42조)는 발명의 설명과 청구범위의 기재 요건을 규정한다. 특정 문구·문장 수의 충족을 이 요건의 충족으로 대신하지 않는다.

[특허법 제47조](https://www.law.go.kr/법령/특허법/제47조)의 보정 범위는 명세서·도면과 관련된다. 청구항 텍스트가 그대로라는 사실만으로 본문에 새 내용을 추가할 수 있다고 판단하지 않는다. 개별 사건의 법적 결론은 해당 시점·절차·최초 자료를 확인해야 한다.

- DOCX 예제 실제 생성 후 ZIP/XML, 제목, 청구항 헤더·문언 확인. Word/PDF 시각 검사는 미실행.

자동 검사는 구조·링크와 스크립트 회귀를 확인한다. [평가 사례](../evals/skill-cases.json)는 별도 실행·판정용이며 테스트 파일이 있다는 이유로 모델 성능 향상을 주장하지 않는다. ITER 10 원문은 명시적 문체 호환 요청용으로 남겼다. 도면 에디터와 모든 외부 문서 도구의 실행을 이번 지침 정리만으로 검증한 것으로 보지 않는다.
