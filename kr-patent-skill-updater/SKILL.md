# 한국 특허 스킬 개선

사용자가 스킬 개선·회고 반영을 요청했을 때 실제 실패나 피드백으로 입증되는 변경만 반영한다. 명세서 작업이 끝났다는 이유로 스킬을 자동 수정하거나 매번 회고를 제안하지 않는다.

## 개선 절차

1. 관찰된 문제, 재현 입력, 원하는 결과를 짧게 정리한다. 단일 사건의 고객 선호·문체·수치를 보편 규칙으로 만들지 않는다.
2. 대상 스킬과 참조자료·스크립트의 기존 지침을 읽고 원인을 찾는다. 고정된 '5개 스킬' 분류 대신 실제 책임에 따라 배치한다.
3. 기존 규칙의 수정·병합·삭제로 해결할 수 있는지 먼저 확인한다. 선택적인 도메인 사례는 필요한 참고자료에 둔다. 변경 이력은 Git에 남기고 SKILL.md에 끝없이 쌓지 않는다.
4. 사용자가 반영을 요청한 범위는 바로 수정한다. 제안·회고만 요청받았으면 변경안까지만 제공한다. 범위를 넓히는 변경은 따로 구분한다.
5. 호출 조건과 상대 링크를 검증하고, 스크립트를 바꿨으면 실행한다. 실제 실패 사례와 인접한 정상 사례를 재확인한다. 근거 없는 성능 향상 수치는 쓰지 않는다.

개선 내용에는 사건 식별정보·고객명·비공개 발명 내용을 넣지 않는다. 일반화할 수 없는 사실은 사건별 자료에만 남긴다.

## 기존 누적 섹션 호환 도구

이미 누적 섹션을 사용하는 문서에 짧은 항목을 명시적으로 추가할 때만 [append_learning.py](scripts/append_learning.py)를 쓴다. 기본 개선 방식은 기존 지침 직접 편집이다.

```bash
python scripts/append_learning.py --skill-path /path/to/SKILL.md --list
python scripts/append_learning.py --skill-path /path/to/SKILL.md --item "검증된 개선 항목" --dry-run
python scripts/append_learning.py --skill-path /path/to/SKILL.md --item "검증된 개선 항목"
```

스킬 디렉터리에서 실행하거나 스크립트의 실제 경로를 사용한다. 섹션이 없으면 자동 생성하지 않는다. 도구는 중복 항목을 건너뛰고 변경이 있을 때만 백업한다. 새 원칙의 타당성은 도구가 판단하지 않으므로 변경 전 검토가 필요하다.

## 결과

수정 파일과 이유, 제거·통합한 지침, 검증 결과와 한계를 보고한다. 저장소 변경 요청에 대한 브랜치/PR 생성은 해당 요청 범위에서 처리하며 배포·병합을 암묵적으로 추가하지 않는다.
