# 한국 특허 명세서 정합성 점검

청구항·본문·도면의 실제 결함을 근거와 함께 보고한다. 검토만 요청하면 원문을 수정하지 않는다. 수정까지 요청받았으면 그 범위의 명확한 오류를 고치고 실질적 선택이 필요한 항목을 분리한다.

## 자료와 점검 범위

정본과 출원 전/후 상태를 확인한다. DOCX 포함 도면과 외부 도면의 버전이 같은지 먼저 대조한다. PBD·벡터 원본의 텍스트와 연결 구조를 우선 활용하고, 래스터 도면은 시각 확인 및 필요 시 OCR로 읽는다. OCR을 못 했거나 도면이 없으면 '미검증'으로 기록한다.

## 점검

| 영역 | 확인할 결함 |
|---|---|
| 청구항 | 인용 누락·순환, 선행 기재, 용어 불일치, 허용되지 않은 원문 변경 |
| 청구항 ↔ 본문 | 각 구성·관계·수치 한정의 설명 근거, 종속항 조건의 누락·모순, 선택사항을 필수로 오인시키는 서술 |
| 부호 | 같은 부호가 다른 객체를 가리킴, 동일 객체의 불일치 명칭, 입력과 산출 객체의 혼동 |
| 도면 ↔ 본문 | 실제 객체·연결·분기·라벨·도면 번호와 설명의 불일치, 실제로 없는 도면 인용 |
| 기술 설명 | 판단 근거 누락, 입출력 단절, 물리적 배치·작동 모순, 정의·수식 변수·단위의 불명확성 |
| 과제·효과 | 근거 없는 성능·효과, 선택적 구현 효과의 과도한 일반화, 자료와 반대되는 인과 |
| 편집 | 내부 주석·미완성 마커 잔존, 요청된 서식과의 차이, 사용자 편집 유실 |

청구항별로 **구성/한정 → 본문 위치 → 도면(해당 시) → 판정**을 기록한다. S4에 전용 문단이 없다고 곧바로 뒷받침 결함으로 판정하지 않고 명세서 전체를 확인한다. 텍스트로 충분한 설명에 도면을 항마다 의무화하지 않는다.

용어·부호 비교에서는 `(110)`과 `110`, 한글/영문 병기, 문법상 조사 차이를 의미 불일치와 구별한다. '상기', '종래', '구성되는' 등의 검색 결과는 검토 후보이며 자동 결함이나 일괄 치환 지시가 아니다. 청구항·요약·인용문에는 본문 문체 규칙을 그대로 적용하지 않는다.

## 우선순위와 출력

- **A**: 기술적 모순, 핵심 설명 근거 부재, 청구항 무단 변경 등 결과를 실질적으로 바꾸는 문제.
- **B**: 해석을 어렵게 하는 불명확성, 누락된 참조 등 보완이 필요한 문제.
- **C**: 사용자가 선택한 문체·서식상의 개선. 실제 의미 영향이 있으면 그 근거로 재분류한다.

각 항목에 ID, 위치, 원문 또는 관찰 사실, 판단 근거, 수정안, 영향/확인 필요 사항을 적는다. 미제공·판독 불가 자료는 별도 미검증 목록에 둔다. 임의 점수나 '결함 0이므로 출원 가능' 결론을 내리지 않는다.

ITER 10 등 특정 문체 검토는 명시적으로 선택된 경우에만 `kr-patent-detail-description-review`에 맡긴다. 반복 정제 요청은 `kr-patent-ralph-loop`로 이어간다. 수정 후에는 영향받은 청구항 근거·부호·도면을 함께 재검증한다. tracked changes가 요청되면 원본을 보존하고 변경 추적을 검증한다. 지원 도구가 없으면 그 한계를 밝히고 수정안·diff를 제공한다.

출원 후 보정은 본문·도면 변경도 최초 출원 자료와 대조한다. 신규사항 검토를 청구항 텍스트 동일성 검사로 대신하지 않는다. 법적 결론이 필요한 항목은 현행 공식 법령·심사기준과 근거 위치를 확인한다.
