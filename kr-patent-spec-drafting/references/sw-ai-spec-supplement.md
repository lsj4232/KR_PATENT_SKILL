# AI·SW·제어 구현 설명

해당 기술을 작성할 때만 사용한다. 아래 항목은 누락을 찾는 관점이며 모든 발명에 모두 추가하는 목록이 아니다.

| 유형 | 확인할 기술 내용 |
|---|---|
| AI/ML | 입력·출력, 학습/추론 구분, 데이터 구성·라벨·전처리, 관련 모델 구조와 학습 방법, 실제 평가 근거 |
| 데이터 처리 | 처리 주체, 데이터 구조, 변환·생성 단계, 모듈 간 전달, 식별자 승계, 관련 예외 처리 |
| 제어 | 센서 입력, 판단 근거, 제어 명령, 구동부, 피드백, 실제 설계된 안전 조건 |
| 시스템/네트워크 | 주체별 역할, 통신 경로, 상태 동기화, 관련 권한과 오류 처리 |

설명되지 않은 모델 구조·손실함수·임계값·학습 결과는 발명자 확인 사항으로 남긴다. 모든 모델 이름이나 기술 유행어를 보일러플레이트로 열거하지 않는다.

## 흐름과 예시

처리 흐름에서 입력·중간 결과·최종 결과가 어디서 만들어지고 소비되는지 이어 쓴다. 실제 객체와 기능 구분용 블록을 구별하고, 서로 다른 산출물에 같은 부호를 재사용하지 않는다.

구체적 예가 이해를 돕는다면 자료에 근거한 입력 → 처리 → 출력 사례를 넣는다. 설명용 가정 예시는 그렇게 표시하며 실험·검증 결과처럼 보고하지 않는다. 기본/변형/조건부/대체 실시예는 필요한 유형만 작성한다.

## 범위와 문체

- 600문장·25,000자·30페이지, 최소 종속항 수, 보완 문장 수를 요구하지 않는다.
- 용어 정의와 동작 설명이 충분하면 같은 내용을 여러 층으로 반복하지 않는다.
- '변환'은 입력 객체가 바뀌는지, '생성'은 별도 결과가 만들어지는지 구별해 선택한다. 명칭의 일관성보다 기술적 의미를 먼저 확인한다.
- '상기'나 가능형 어미는 문맥과 사용자 문체에 맞춘다. 접속어·종결어미 빈도를 품질 기준으로 쓰지 않는다.
- 자료의 충돌은 출처와 버전을 함께 보고하며 발명자 진술이라는 이유만으로 다른 자료를 조용히 덮지 않는다.
