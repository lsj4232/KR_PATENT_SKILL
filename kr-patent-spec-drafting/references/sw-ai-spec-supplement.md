# AI·SW·제어 구현 설명

해당 기술을 작성할 때만 사용한다. 아래 항목은 누락을 찾는 관점이며 모든 발명에 모두 추가하는 목록이 아니다.

| 유형 | 확인할 기술 내용 |
|---|---|
| AI/ML | 입력·출력, 학습/추론 구분, 데이터 구성·라벨·전처리, 관련 모델 구조와 학습 방법, 실제 평가 근거 |
| 데이터 처리 | 처리 주체, 데이터 구조, 변환·생성 단계, 모듈 간 전달, 식별자 승계, 관련 예외 처리 |
| 제어 | 센서 입력, 판단 근거, 제어 명령, 구동부, 피드백, 실제 설계된 안전 조건 |
| 시스템/네트워크 | 주체별 역할, 통신 경로, 상태 동기화, 관련 권한과 오류 처리 |

설명되지 않은 모델 구조·손실함수·임계값·학습 결과는 발명자 확인 사항으로 남긴다. 모든 모델 이름이나 기술 유행어를 보일러플레이트로 열거하지 않는다.

## 흐름과 예시

처리 흐름에서 입력·중간 결과·최종 결과가 어디서 만들어지고 소비되는지 이어 쓴다. 실제 객체와 기능 구분용 블록을 구별하고, 서로 다른 산출물에 같은 부호를 재사용하지 않는다.

구체적 예가 이해를 돕는다면 자료에 근거한 입력 → 처리 → 출력 사례를 넣는다. 설명용 가정 예시는 그렇게 표시하며 실험·검증 결과처럼 보고하지 않는다.

## 풀명세서 작성 기준

AI·소프트웨어·제어·시스템 분야의 풀명세서에는 다음 기준을 기본 적용한다. 사용자가 분량이나 작업 범위를 지정하면 그 요청을 우선한다.

- **실시예 본문 분량.** 【발명을 실시하기 위한 구체적인 내용】은 600문장·25,000자·30페이지 이상을 권장한다. 청구항·요약서·도면 페이지를 제외하고 본문 분량을 확인한다. 페이지 수는 출력본이 있을 때 확인한다.
- **실시예 4계층.** 기본 실시예(L1)는 전체 구성과 동작을 연결한다. 변형 실시예(L2)는 기본안 일부를 바꾼 예를 설명한다. 선택 실시예(L3)는 적용 조건과 조건을 충족했을 때의 동작을 설명한다. 대체 실시예(L4)는 같은 역할을 다른 구성이나 방식으로 구현하는 예를 설명한다. 본문을 설계할 때 네 계층을 모두 배치하고 기본안과의 차이를 밝힌다.
- **구성요소별 3단 서술.** 청구항의 각 구성요소를 정의 → 구체화 → 조건·변형의 순서로 각각 설명한다. 먼저 대상과 역할을 정하고, 다음에 입력·처리·출력 또는 결합 관계를 구체화하며, 마지막으로 적용 조건이나 변형에 따른 동작 차이를 설명한다. 같은 구성요소를 세 번 다루되 각 설명에 새로운 기술 정보를 담는다.
- **보완 문단 분량.** 본문에 삽입하는 보완 문단은 건별로 15~25문장으로 작성한다. 보완 대상에 맞춰 정의, 구현 조건, 처리 순서, 예시, 근거가 있는 변형과 효과를 구체적으로 서술한다. 이 기준은 해당 분야 본문 보완만 요청된 경우에도 적용한다.

검토 시 실시예 본문의 분량, 4계층의 배치, 구성요소별 3단 서술, 보완 문단별 문장 수를 확인한다. 근거가 부족하면 확인이 필요한 항목과 충족하지 못한 기준을 기록한다. 제공 자료에 없는 구성·수치·실험 결과를 확정 사실로 채우지 않는다.

## 범위와 문체

- '변환'은 입력 객체가 바뀌는지, '생성'은 별도 결과가 만들어지는지 구별해 선택한다. 명칭의 일관성보다 기술적 의미를 먼저 확인한다.
- '상기'나 가능형 어미는 문맥과 사용자 문체에 맞춘다. 접속어·종결어미 빈도를 품질 기준으로 쓰지 않는다.
- 자료의 충돌은 출처와 버전을 함께 보고하며 발명자 진술이라는 이유만으로 다른 자료를 조용히 덮지 않는다.
