# 도면 세트 설계

도면이 없거나 세트를 재구성할 때 사용한다. 장수·챕터 수를 고정하지 않고 기술 관계가 잘 보이는 구성을 택한다.

1. 청구항의 핵심 구성과 관계, 본문에서 설명할 흐름을 정리한다.
2. 구성도·흐름도·개념도·단면도 등 설명에 필요한 유형을 선택한다. 하나의 도면이 여러 청구항을 설명하거나 본문만으로 설명되는 사항도 허용한다.
3. **도면 번호 / 설명 대상 / 관련 청구항 / 본문 위치 / 실제 원본 또는 작성 예정**을 표로 연결한다. 미작성 도면을 완성된 자료로 인용하지 않는다.
4. 객체의 명칭·부호·입출력·연결을 정하고 실제 흐름과 비교한다. 순수 기능 블록을 별도 하드웨어인 것처럼 그리지 않는다.
5. 독립항의 공통 구성과 선택적 세부 구현을 구분한다. 별도 도면, 서브도면, 점선 영역 등 적절한 수단을 사용한다.

## 라벨과 배치

라벨은 핵심 의미를 보존하면서 읽을 수 있는 길이로 쓴다. 청구항 원문 그대로 표시하는 방식은 사용자가 선택한 경우에 적용하고, 축약 시 관계·조건이 빠지지 않았는지 대조한다. 원문 복사 여부를 법적 뒷받침의 유무와 동일시하지 않는다.

객체명·부호가 실제 도형을 가리키고 화살표의 시작·끝과 분기 조건이 분명한지 확인한다. 수치·표·예시 데이터의 포함 여부는 관련성과 목적에 따라 정한다. 모든 수치를 제거하거나 한 장에 하나의 변환만 허용하지 않는다.

## 제작·검증

- 새 블록도는 `patent-block-diagram`, 기존 PBD는 `patent-block-diagram-refine`을 사용할 수 있다.
- PBD 텍스트·연결 구조와 렌더 이미지를 함께 확인한다. 원본 JSON만 맞아도 라벨 잘림·겹침이 있을 수 있다.
- 본문·도면·청구항의 버전을 함께 인계하고 도면 번호나 부호 변경의 영향을 갱신한다.
- 관할별 도면·서식 요구를 검토해야 하면 최신 공식 기준을 확인한다. 특정 도면 형식이 권리범위를 보장한다고 단정하지 않는다.
