# 도면 세트 설계 (S12 확장)

**적용 시점**: S12 【도면의 간단한 설명】 작성 전. 특히 **발명자가 도면을 제공하지
않은 건**에서는 S11 서두보다 S12를 먼저 수행한다. 도면이 확정되어야 서두의 시스템
정의와 용어 정리를 부재번호에 맞추어 쓸 수 있다.

---

## 0. 원칙: 도면 설계가 명세서를 결정한다

도면은 명세서의 부속물이 아니라 **명세서 구조의 결정 요인**이다.

- 한 장의 도면이 한 챕터 또는 한 하위 절에 대응한다.
- 도면의 순서가 챕터 순서가 된다.
- 도면에 등장하는 객체의 순서가 부재번호의 도입 순서가 된다.

따라서 도면 세트를 확정하지 않고 챕터 목차를 먼저 세우면 나중에 양쪽이 어긋난다.

역방향도 성립한다. **종속항의 축 구성이 곧 도면 세트의 설계도**다. 종속항을 축별
사슬로 설계했다면 그 축 목록이 그대로 개념 전개 도면의 목록이 된다. 청구항 설계
단계에서 확정한 축을 S12에서 다시 정의하지 않는다.

---

## 1. ★ 커버리지 우선 원칙

**청구항 축의 도면 뒷받침이 장수에 우선한다.** 장수를 이유로 축을 생략하거나 병합하지
않는다.

각 도면에 대하여 **대응 청구항**을 명시하고, 역으로 각 청구항에 대하여 그것을
뒷받침하는 도면이 있는지 확인한다. 도면 뒷받침이 없는 청구항은 명세서 서술만으로
지지되므로, 그 상태가 의도된 것인지 판단해야 한다.

```
[도 N] {제목}
- 대응 청구항: 제13항, 제14항
  (이 장이 빠지면 두 종속항이 도면 뒷받침을 잃는다)
```

장수가 목표치를 초과하면 **초과 사실과 장별 내역(어느 축, 어느 청구항 때문인지)을
보고하고 그대로 진행한다.** 압축은 사용자가 명시적으로 선택한 경우에만 수행하며,
그때에도 **압축으로 도면 뒷받침을 잃는 청구항 목록을 반드시 함께 보고한다.**

---

## 2. 세트 골격과 축별 예산

도면 수는 층별 산식으로 계산하기보다 **고정 골격에 축별 예산을 더하는** 방식으로
산정한다.

| 위치 | 내용 | 장수 |
|---|---|---|
| 출원인 표준 템플릿 | 출원인이 전 건에 공통으로 쓰는 도면이 있으면 그대로 재사용(발명 무관, 고정 스펙) | 고정 |
| 시스템 도면 | 장치 구성 블록과 사용 맥락을 한 장에 결합. 배치 변형은 서브도면으로 | 1 |
| 전체 흐름도 | 제1항(방법 독립항) 전문 흐름도 | 1 |
| (조건) 학습 독립항 존재 | 흐름도를 학습과 추론 서브도면으로 분할하거나, 학습 흐름도 1장과 학습 파이프라인 데이터 흐름도 1장 추가 | +1~2 |
| (조건) 추가 방법 독립항 | 세트 후반에 전문 흐름도와 개념도 | +1~2 |
| 본발명 상세 | 개념 전개 연작 + 응용 장면 | 축별 예산 |

**본발명 상세의 산정 기준은 청구항 특징 축의 수**다. 종속항 그룹(축)당 개념 전개
1장을 기본으로 한다.

**표 형태의 데이터는 도면으로 승격하지 않는다.** 분포, 임계값, 성능 예시 같은 수치
자료는 명세서 본문 전용이다. 다만 메모리 내부 구조나 대응 관계와 같이 구조 자체가
청구된 종속항은 구조도 1장으로 그린다.

## 3. 한 장 = 한 정보 변환

개념 전개 연작은 **한 장에서 하나의 정보 변환만** 다루고, **직전 장의 산출물 부호를
입력으로 받아** 다음 정보를 생성한다.

```
도 A: 입력 100 -> [변환 1] -> 산출물 110
도 B: 110 -> [변환 2] -> 산출물 120
도 C: 120 -> [변환 3] -> 산출물 130
```

이 구조가 지켜지면 명세서 본문에서도 각 챕터가 앞 챕터의 산출물을 받아 이어지므로,
브릿지 문장이 자연스럽게 도출되고 의미 비약이 생기지 않는다.

- 한 장에 두 개 이상의 변환을 담으면 그 장의 서술이 두 챕터 분량이 되어 챕터와 도면의
  대응이 깨진다.
- 반대로 한 변환을 두 장에 나누면 부호 승계가 불필요하게 늘어난다.

**데이터에서 데이터로 직결하지 않는다.** 변환에는 그 변환을 수행하는 주체 또는 처리
박스를 경유시킨다. 명세서 본문에서 "무엇이 그 변환을 수행하는가"를 서술할 근거가 된다.

## 4. ★ 흐름도 박스의 문언 (정본 선택 항목)

> **정본 선택**: 아래 "청구항 원문 그대로" 방식은 2026.09 개정본의 규범이다. 기존
> 사건에서 요약형 박스로 작성한 세트가 있으면 **한 건 안에서는 한 방식으로 통일**한다.
> 신규 건의 default는 원문 방식으로 한다.

방법 독립항의 전문 흐름도에서 **각 단계 박스에는 해당 청구항 단계의 문언을 그대로
기재한다.** 핵심 키워드만 뽑아 요약하지 않는다.

```
(청구항 제1항 제1단계)
  원자력 인허가 문서로부터 획득된 문서 데이터에 포함된 참조 정보를 식별하고,
  상기 참조 정보가 지시하는 참조 대상의 이용 가능 여부를 나타내는 참조 상태 정보를
  생성하는 단계;

(잘못된 박스 문언, 요약)
  참조 대상의 이용 가능 여부 판정

(권장 박스 문언, 원문)
  원자력 인허가 문서로부터 획득된 문서 데이터에 포함된 참조 정보를 식별하고,
  참조 정보가 지시하는 참조 대상의 이용 가능 여부를 나타내는 참조 상태 정보를 생성
```

**옮길 때의 조정은 다음 네 가지뿐이다.**

| 조정 | 내용 |
|---|---|
| 「상기」 삭제 | 도면은 문언이 독립적이고 공간이 제한되므로 뺀다 |
| 말미 처리 | 「~하는 단계」를 명사형으로 줄이거나 그대로 둔다. 세트 전체에서 하나로 통일 |
| 세미콜론 삭제 | 청구항의 구분 기호는 옮기지 않는다 |
| 줄바꿈 | 의미 단위로 끊는다. 조사 뒤나 쉼표 뒤에서 끊고 명사구 중간에서 끊지 않는다 |

**내용을 줄이거나 바꾸는 조정은 하지 않는다.** 어절을 빼거나 동의어로 치환하거나
순서를 바꾸지 않는다.

**이유 3가지**

1. **도면 자체가 청구항 뒷받침 자료가 된다.** 박스에 청구항 문언이 그대로 있으면
   심사관이 도면만으로 청구항과 대조할 수 있다. 요약하면 도면은 참고 자료로 격하된다.
2. **보정 시 파급 범위가 명확해진다.** 청구항을 보정하면 흐름도 박스도 함께 보정해야
   하는데, 원문이면 1대1 대응이라 어디를 고칠지가 자명하다.
3. **본문 인용과 문언이 일치한다.** 본문에서 "~하는 처리(SNNN)가 진행될 수 있다"로
   서술할 때 그 문언과 도면 박스와 청구항이 모두 같아진다.

### 흐름도의 형식

- **세로 단일열**로 배치하고 수직 실선 화살표로 잇는다.
- 박스는 **넓은 다행 박스**로 하고 **3줄까지** 허용한다.
- 단계 부호는 **우측 리더선**으로 박스 외부에 붙인다
  (도면 박스 안 괄호 표기 금지 규칙과 동일).
- 시작 및 종료 단자는 두어도 되고 생략해도 된다. 세트 전체에서 통일한다.

**박스가 3줄에 들어가지 않으면 그 단계가 과적재된 신호**일 수 있다. 다만 생성과 그
부산물이 하나의 단계로 묶인 경우라면 3줄을 채우는 것이 정상이다. 4줄을 넘어가면
청구항 설계로 되돌아가 단계를 나눌지 검토한다.

### 종속항의 흐름도 처리

전문 흐름도는 **독립항의 단계만** 담는다. 종속항의 추가 단계나 한정은 다음 중 하나로
처리한다.

- 별도의 세부 흐름도를 두고 그 안에서 하위 단계로 전개
- 전문 흐름도에 점선 박스로 부가하되 독립항 단계와 시각적으로 구분
- 개념 전개 도면에서 해당 축을 다루고 흐름도에는 넣지 않음

독립항 단계와 종속항 단계를 같은 실선 박스로 나란히 두면, 종속항의 한정이 독립항의
필수 구성인 것처럼 읽힌다.

## 4-1. ★ 광의 도면과 구체화 도면의 2층 구조 (해외출원 대비)

**한국에서는 특별히 문제되지 않지만, 유럽(EPO)과 중국(CNIPA)에서는 도면을 근거로
청구항을 한정해석하거나 도면에 의해 뒷받침되지 않는다는 지적이 제기된다.** 흐름도를
한 장만 두고 그 장을 구체적으로 그리면, 그 구체 수준이 청구항 해석 범위로 읽힌다.

같은 흐름을 **두 층으로 나누어 그리는 것이 정석**이다.

| 층 | 내용 | 장수 | 대응 |
|---|---|---|---|
| 1층 (광의) | 각 단계 또는 각 단계의 워딩을 넓힌(간략화한) 전문 흐름도 | 1 | 독립항 |
| 2층 (구체) | 1층 단계를 하위 단계로 분해하거나 워딩을 구체화한 흐름도 | 예시 수만큼 | 종속항, 실시예 |

- **1층이 없으면 한정해석의 근거가 된다.** 구체 도면 하나가 발명의 전부로 읽힌다.
- **2층이 없으면 뒷받침 흠결 지적을 받는다.** 구체 실시 형태가 도면 뒷받침을 잃는다.
- **구현 예시가 여러 개면 예시마다 한 장씩 둔다.** 한 장에 여러 예시를 겹쳐 그리면
  예시 하나가 다른 예시의 필수 구성처럼 읽힌다.
- 단계 부호는 승계 관계가 드러나게 부여한다(1층 S310 -> 2층 S311, S312, S313).

**4절의 "청구항 원문 그대로" 규칙과의 관계**: 청구항 문언 자체가 그 건에서 가장 넓은
워딩이므로, **1층이 곧 원문 이관 층**이다. 두 규칙은 충돌하지 않는다. 워딩을 넓힌다는
것은 청구항보다 더 넓게 쓰라는 뜻이 아니라, **구체 실시 형태의 어휘를 1층에 끌어들이지
말라**는 뜻이다. 구체 어휘는 전부 2층으로 내린다.

## 5. 응용 장면 도면

UI나 서비스 화면이 실시예의 응용 개시 창구인 건에서는 **입력 장면 1장과 출력 장면
1장을 쌍으로** 그린다.

두 장을 인접 배치하지 않는다. **입력 장면은 파이프라인 초반에, 출력 장면은 복원 및
출력 개념 도면 뒤에** 배치한다. 그래야 그 사이의 개념 전개 연작이 입력에서 출력에
이르는 과정으로 읽힌다.

장면을 추가하면 장면당 2장씩 늘어나므로, 장면의 개수와 소재는 착수 전에 확정한다.

## 6. 선 및 도형의 의미론

세트 전체에서 일관되게 적용하고, 도면 작업지시서에 명시한다.

| 요소 | 의미 |
|---|---|
| 실선 화살표 | 데이터 흐름 |
| 점선 연결 | 산출, 파생, 재사용 또는 할당 관계 |
| 점선 사각형 | 개념 그룹 또는 주목 영역 |
| 마름모 | 조건 분기 |
| 밑줄 부호 | 도면 전체 또는 시스템 전체를 지시하는 부호 |

블록 내부의 계층 중첩은 3단까지 허용한다. 그 이상은 별도 도면으로 분리한다.

## 7. ★ 도면 용어는 청구항 확정 어휘로 통일

발명자료의 모듈명이나 실무 용어를 도면에 그대로 쓰지 않는다.

```
(발명자료) PIM, NPU, 압축 ViT 인코더 모듈
(도면)     메모리 내 연산 장치, 온칩 연산 장치, 제1 생성 모델
```

도면의 텍스트가 청구항 용어와 다르면 본문이 도면을 설명할 때 어느 쪽 용어를 쓸지
흔들리고, 결국 "청구항 용어 변경 금지" 규칙이 도면 단계에서 깨진다.

## 8. 도면 착수 전 확인 사항

질문은 **도면 품질을 실제로 바꾸는 것만** 하고, 한 번에 3개 이하로 묶는다. 발명자료나
청구항에서 답을 알 수 있으면 묻지 않는다.

| 확인 항목 | 묻는 이유 |
|---|---|
| 응용 장면의 개수와 소재 | 장수에 직접 영향(장면당 2장) |
| 폼팩터 | 화면 도면의 기준 기기 |
| 반드시 포함하거나 제외할 도면 | 산정 모델과 별개의 요구 |
| 자사 명칭과 제3자 명칭의 구분 | 제3자 상표는 가상명으로 치환 |
| 기존 도면 세트의 존재 | 같은 출원인의 선행 세트가 있으면 선 스타일과 부호 관행을 그 세트에 맞춤 |

**응용 장면을 물을 때는 후보를 먼저 제안한다.** 발명자료의 적용 분야 서술에서 후보
장면 2~4개를 도출하여 제시하고 선택을 받는다. 빈손으로 "어떤 장면을 원하는지" 묻지
않는다.

**묻지 않는 것**: 판형(콘텐츠 종횡비로 자동 결정), 부호 번호(규칙으로 결정론적 채번),
청구항이나 발명자료에 이미 답이 있는 것.

## 10. ★ 도면 작업지시서

도면을 외부 도면사나 생성 도구에 맡기는 경우, 지시서를 다음 구조로 작성한다. 구두
설명이나 요약 지시로는 누락과 임의 변경이 반복된다.

### (0) 완결성 계약 (지시서 최상단)

```
제출물은 정확히 N장이다. 어떤 장도 생략, 병합, 분할하거나 순서를 바꿀 수 없다.
그리기 어렵거나 정보가 부족한 장이 있으면 그리지 말고 해당 도 번호를 명시하여 질문으로
반환한다. 임의 생략은 실패로 간주한다.

부호표가 유일한 진실이다. 부호의 추가, 삭제, 재부여 및 번호 변경을 금지한다. 용어는
부호표의 명칭을 글자 그대로 사용한다.

쪽번호는 제출 순번이며 도면 라벨 번호와 무관하다. 결번이나 중복이 있으면 실패로
간주한다.
```

**장수가 많다는 이유로 장을 줄이거나 병합하는 것은 작업자의 권한이 아니다.** 이 문장을
계약에 명시한다.

### (1) 매니페스트 왕복

- **작업 전**: 작업자가 "쪽, 라벨, 판형, 작성 가능 여부, 질문" 5열의 계획 매니페스트를
  전 장에 대하여 회신. 작성 불가 행이 있으면 답변 후 착수.
- **작업 후**: "쪽, 라벨, 포함된 부호 전수" 3열의 제출 매니페스트 첨부. 발주 측이
  스펙 카드와 대조.

### (2) 출력 규격

용지, 페이지당 도면 수, 선화 방식, 라벨 위치, 가로형 도면의 회전 방향, 선 및 도형의
의미론, 리더선 스타일을 명시한다.

### (3) 부호표

부호, 명칭, 등장 도면, 파생 규칙의 4열 전수 표. 이것이 유일한 진실임을 계약에 명시.

### (4) 형식 앵커

기존 세트나 샘플이 있으면 각 샘플이 어느 유형의 형식 기준인지 매핑한다. 작업자는 새
장을 그릴 때 같은 유형의 앵커 장과 동일한 시각 문법(박스 비례, 선폭, 부호 배치)을
사용한다.

### (5) 장별 스펙 카드 (전 장, 기계 대조 가능 형태)

```
[도 N] 제목
- 판형: 세로 또는 가로
- 유형: 흐름도, 개념 전개, 응용 장면, 시스템, 데이터 흐름, 템플릿 재생산
- 필수 부호: 쉼표로 전수 나열
- 필수 텍스트: 박스 및 라벨 문구 전수 나열, 문구 변경 금지 항목 표시
- 관계 목록: A -> B (실선, 라벨), C --> D (점선, 산출) 형식으로 전수
- 레이아웃 힌트: 2~3줄
- 대응 청구항: 이 장이 빠지면 뒷받침을 잃는 청구항
```

**필수 부호와 필수 텍스트는 전수 목록**이며, 하나라도 빠지면 해당 장은 불합격이다.

### (6) 자가 검증 체크리스트

작업자가 제출 직전에 수행하고 결과를 첨부. **총 장수를 직접 세어 숫자를 기입하게 하는
항목**을 포함시킨다.

### (7) 금지 사항 요약

임의 생략, 장 병합, 부호 재부여, 용어 치환, 쪽번호 결번, 판형 임의 변경, 앵커 형식
이탈. 판단이 애매하면 그리지 말고 질문.

### 생성 도구용 프롬프트

생성형 도구에 맡기는 경우에도 위 구조를 유지하되, 공통 지시(흑백 선화, 색상 및 아이콘
금지, 부재번호 표기 방식, 실존 명칭 금지)와 도면별 배치 지시를 담고 **생성 후 확인
사항**을 함께 제시한다. 확인 사항에는 그 건에서 틀리기 쉬운 지점을 구체적으로 적는다.

```
(예) 프로세서 내부 영역이 점선으로 그려졌는가. 실선이면 다시 요청해야 한다.
(예) 강조 경로가 제4열 노드를 포함하지 않는가. 포함되면 전파 범위 한정의 취지가
     어긋난다.
```

## 11. S12 자가 점검

- [ ] 청구항과 도면의 커버리지 매핑을 작성했는가
- [ ] 도면 뒷받침이 없는 청구항 목록을 파악하고 있는가
- [ ] 장수를 이유로 축을 임의 생략하거나 병합하지 않았는가
- [ ] 도면의 텍스트가 청구항 확정 어휘로 통일되었는가
- [ ] 흐름도 박스 문언 방식(원문 또는 요약)이 세트 전체에서 하나로 통일되었는가
- [ ] 박스가 3줄 이내인가, 초과 시 단계 과적재 여부를 검토했는가
- [ ] 전문 흐름도에 종속항의 한정이 독립항 단계처럼 섞여 있지 않은가
- [ ] 개념 전개 도면에서 한 장이 하나의 정보 변환만 다루는가
- [ ] 직전 장의 산출물 부호가 다음 장의 입력으로 승계되는가
- [ ] 데이터에서 데이터로 직결된 화살표가 없는가(처리 주체를 경유하는가)
- [ ] 표 형태의 수치 자료를 도면으로 승격하지 않았는가
- [ ] 응용 장면의 입력과 출력이 분리 배치되었는가
- [ ] (해외출원 대비 건) 흐름도가 광의 1층과 구체 2층으로 나뉘어 있는가. 구현 예시가 복수이면 예시마다 별도 장인가
- [ ] 도면 작업지시서에 완결성 계약, 부호표 및 장별 스펙 카드가 포함되었는가
