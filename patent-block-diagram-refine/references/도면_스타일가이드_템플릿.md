# 특허 도면 수정 프롬프트 가이드 (범용 템플릿)

특허 명세서 도면 세트를 `patent-block-diagram` 스킬(특허 블록도 에디터)로 수정할 때
참조하는 범용 문서. 사무소 하우스 스타일(도형 용법·글자 크기·레이아웃·부호 규칙)을
고정해, 어떤 사건이든 기존 도면과 톤이 어긋나지 않게 편집하기 위한 것이다.

**사용법**: 이 파일을 사건 폴더로 복사한 뒤, `⟨...⟩` 로 표시된 칸을 그 사건 값으로 채운다.
새 사건 시작 시 `§2 부호 체계`와 `§3 도면 대장`만 채우면 나머지는 그대로 쓴다.

---

## 0. 작업 전 필수 컨텍스트 (사건별로 채움)

- **원본 위치**: `⟨도면 폴더 경로⟩\도면N.pbd` (파일명에 공백 있으면 따옴표 필수)
- **백업/산출**: `⟨…⟩\pbd_bak\`, PNG는 `⟨…⟩\PNG_out\`
- **명세서 최신본**: `⟨명세서 최신 docx 경로⟩`
  - 도면 부호·단계명은 이 명세서 본문·부호의 설명과 1:1로 일치해야 한다.
    부호를 바꾸면 명세서도 같은 세션에서 수정 대상이다.
- **편집 도구**: 스킬 `patent-block-diagram` (앱 `$APP_DIR`)
- **철칙**: 렌더 없이 좌표만 믿지 않는다. 수정 → CDP 포트로 렌더 → PNG를 Read로 육안 확인 → 보정 반복.

수정 착수 프롬프트 골격:

```
patent-block-diagram 스킬로 "⟨경로⟩\도면N.pbd"를 연다.
아래 [수정 지시]대로 박스/화살표/부호를 고치되, 이 사건의
도면_스타일가이드.md(§1 스타일, §2 부호 체계)를 반드시 유지한다.
수정 후 scale 2로 렌더해 겹침·글자잘림·태그물림을 육안 검증하고,
문제 없으면 scale 3 출원용 PNG를 PNG_out\에 저장한다.
[수정 지시]
- ⟨구체 지시⟩
```

## 1. 하우스 스타일 파라미터 (사건 불문 공통 — 그대로 준수)

편집 시 아래에서 벗어나지 않는다. 새 요소는 같은 도면 내 기존 요소 값을 복제한다.

### 1.1 도형(shape) 용법
| shape | 용도 |
|---|---|
| `rect` | 기능 블록, 처리 단계, 사양/데이터 카드, UI 요소 |
| `round` | 흐름도 시작/종료, 개념도의 개체·정의 노드 |
| `diamond` | 판단·분기 |
| `cylinder` | 저장소·DB·입력 데이터 세트 |

> 4형뿐이다. 사람 아이콘·자유곡선·아이소메트릭 불가 → `round` 박스 + "이용자/단말"로 대체하고 사용자에게 보고.

### 1.2 글자 크기(fs) 규약. ★ 절대값이 아니라 캔버스 폭 대비 비율이다

도면은 A4 도면란(약 170 x 255mm)에 종횡비를 유지한 채 축소 배치된다. 따라서 화면상의
`fs` 숫자가 아니라 **인쇄된 문자 높이**가 규정 대상이다. 특허법 시행규칙 별지 도면 규정은
**0.32cm(3.2mm) 이상**이다.

**인쇄 검산식** (착수 전과 렌더 후 두 번 돌린다)

```
s = min(170 / maxX, 255 / maxY)      # mm/px, 종횡비 유지 축소율
인쇄 문자 = fs x s >= 3.2mm
```

비율식으로 환산하면 `fs >= 0.0188 x W`(폭 기준), `fs >= 0.01255 x H`(높이 기준)이고
**둘 중 큰 값**을 쓴다. 사무소 기출원 도면 실측 기준은 그보다 여유 있는 **`fs / W` 약 0.03**이다.

**실무 확정값 (신규 세트의 기본)**

| 항목 | 값 |
|---|---|
| 본문 박스 fs | **44** (여유 있으면 60~76) |
| 부속 목록, 카드 항목 | 44 (본문과 동일. 44 미만으로 내리지 않는다) |
| 패널 제목 | 48 |
| 부호 태그 fs | 본문과 동일 44 |
| 캔버스 폭 | <= 2300px |
| 캔버스 높이 | <= 3400px |

> ⚠️ **구버전 값(fs 16~24)은 쓰지 않는다.** 폭 3248px 캔버스에서 fs 15는 인쇄 0.79mm로
> 규정 위반이다. 기존 세트를 이어 편집할 때만 그 세트의 fs를 따르고, 그 경우에도 검산식을
> 돌려 위반이면 세트 전체 재작도를 사용자에게 보고한다.

**세로로 긴 도면은 높이가 구속조건이 된다.** maxY 4010px 도면에서 fs 48은 3.05mm로 탈락하고
fs 64가 4.07mm로 적합하다. **maxY >= 3600이면 부속 항목에도 fs 48을 쓰지 않는다.**

**이 제약이 레이아웃을 규정한다.** 한글 1자 폭은 대략 fs와 같으므로, fs 44에서 폭 2300px 안에는
**최대 3열**이 들어간다. 4~5열 배치는 폰트를 줄여야 하므로 불가능하고, 넓게 퍼진 도면은
행으로 접거나 (a)(b)(c) 패널로 분할한다. 박스 폭 `w`에 들어가는 글자수는 `w / fs`이므로
(fs 56, w 340이면 6자), 박스를 키우기보다 **3줄로 접어 최장 줄을 줄이는 편**이 비율을 지키기 쉽다.

- 원칙: **한 도면 안에서는 fs를 통일**한다. 정보량이 다른 카드만 예외로 하되 하한은 지킨다.
- 요소가 많아 폭이 넘치면 가로로 늘리지 말고 **세로로 쌓는다**(세로 2배 비율 도면이 정상).

### 1.3 화살표
- 기본 `ortho`(직각). 대각 연결이 불가피할 때만 `straight`.
- **양방향 = 화살표 2개**(A→B, B→A)를 같은 좌표축에 겹친다. 중심축 어긋나면 계단 꺾임(품질 저하).
- 판단 분기: diamond에서 아래(주 경로)·우측(예외) 2방향. `Yes`/`No` 라벨은
  `noFrame:true` 소형 rect(w≈50~60, h50)로 선 옆에 배치.
- 예외/실패 결과 박스는 우측 열에, 앞 단계 회귀 화살표는 `fromOff`/`toOff`로 수동 라우팅.

### 1.4 레이아웃 아키타입
- **세로 흐름도**: 본문 박스 `w=600~640`, 중심 x 동일 정렬(세로 직선), 세로 간격 약 118~130.
- **시스템 블록도**: 중앙 코어(예: 프로세서, 세로통 300×480) + 좌우 기능부 열(각 300×90) + 외곽 컨테이너 rect(`textTop:true`, z 최소) + 외부 엔티티 우측 세로 나열.
- **개념도**: 상단 컨테이너 → 하위 카드 N개(균일 크기) → 하단 컨테이너. 팬아웃/팬인 화살표는 `fromOff` dx로 N등분 정렬.
- **UI 예시도**: 최외곽 윈도우 rect + 타이틀바 + 메뉴버튼 행 + 좌측 패널(체크박스 `☑`/`☐` 텍스트) + 우측 캔버스 + 하단 상세 바. 컨테이너 `textTop:true`, z 최소(1~2). **UI는 부호 태그 미부여가 정상**.
- 캔버스는 내용에 맞춰 자동 확장되나, **폭 2300px, 높이 3400px를 상한으로 관리**한다(§1.2 검산).
  상한을 넘기면 폰트를 줄이지 말고 패널 분할 또는 도면 분할로 해결한다.

### 1.5 z-순서 규약. ★ 컨테이너가 화살표를 삼킨다

컨테이너 rect는 흰색 채움이 있어 z가 더 작은 화살표를 **완전히 가린다**(컨테이너 안쪽
블록들을 잇는 화살표가 통째로 사라진 렌더가 실제로 나온다).

| 요소 | z |
|---|---|
| 컨테이너(점선 박스, 외곽 경계) | 1~8 |
| **화살표** | **15** |
| 박스 | 20 |
| 부호 태그 | 60 |

화살표가 **컨테이너보다 위, 박스보다 아래**여야 화살촉이 박스 테두리에서 자연스럽게 잘린다.

### 1.6 부호 태그 배치. ★ dx, dy는 숫자의 "가운데" 좌표다

`tags[].dx`는 숫자의 왼쪽 끝이 아니라 **중심**이 놓이는 좌표다. 그래서 `dx = w + 40`을 쓰면
숫자의 왼쪽 절반이 박스 안으로 파고든다(fs 56에서 세 자리 숫자 반폭 약 85px).

| 배치 | 값 | 쓰는 곳 |
|---|---|---|
| **위쪽 (기본값)** | `dx = w/2` 또는 `40`, `dy = -70 ~ -75` | 대부분의 박스. 화살표는 박스 중심 높이로 들어오고 스파인은 좌우 바깥을 지나므로 위쪽 좌측은 거의 항상 비어 있다 |
| 오른쪽 바깥 | `dx = w + 140` | **그 행에서 가장 오른쪽 박스에만.** 체인 중간 박스에 쓰면 숫자가 다음 박스 좌상단에 올라앉는다(박스 간격이 보통 120~160px) |
| 왼쪽 바깥 | `dx = -125` | 캔버스 우측 끝 박스 |
| 흐름도 단계부호(S계열) | 박스 **왼쪽** `dx ≈ -62` | 흐름도 주 컬럼. 좌측은 대개 비어 있다 |
| 컨테이너 부호 | 위쪽 바깥 `dx = 60, dy = -45` | 컨테이너 w를 20~30px 넓혀 테두리 물림 방지 |

- **세로로 쌓은 박스에 위쪽 태그**를 쓰면 박스 간 세로 간격을 `h + 100` 이상 잡는다(간격 80에서 물린다).
- **점선 컨테이너 테두리에서 60px 안쪽**에 태그를 두면 숫자가 파선을 타고 앉는다. 컨테이너 높이를
  내부 박스 묶음보다 위아래 각 120px 이상 크게 잡는다.
- `cylinder`는 타원 끝이 박스 폭 끝까지 나오므로 우측 태그에 더 여유가 필요하다.
- 좌측 끝 박스에 음수 `dx`를 주면 좌표가 음수가 되므로, 저장 시 `min(x) < 260`이면 전체를
  오른쪽으로 시프트하는 가드를 둔다.
- **화살표가 드나드는 변에는 태그를 두지 않는다**(지시선이 화살표에 물린다). 유입 화살표가 상단
  중앙이면 태그는 상단 좌측(`dx ≈ 0.16w`)으로.
- 태그 자동 배치는 박스 충돌만 보고 **화살표 경로는 보지 않는다.** 렌더 후 "숫자가 선 위에
  앉았는가"를 육안으로 따로 본다.

### 1.7 ★ 절대 금지 4항 (예외 없음)

① **한 박스에 여러 요소를 줄바꿈으로 나열하지 않는다.** 항목 수만큼 박스를 나눈다(2열 격자로
배치하면 높이가 늘지 않는다). 「객체명 + 그 값」 2줄은 하나의 요소라 허용. 「A 및 B」처럼
동작 2개가 접속사로 묶인 것은 위반이므로 2박스로 나눈다.

② **한 박스에 부호 태그를 2개 이상 달지 않는다.** 부호가 둘 필요하면 박스를 쪼갠다.
**흐름도 단계 박스에는 S부호만** 달고(좌측 S부호 + 우측 요소 부호 조합도 금지), 요소 부호는
옆에 실제 객체 박스를 세워 거기 단다. 같은 종류가 복수면 각 박스에 같은 부호를 반복한다.

③ **자식 박스를 품은 컨테이너에는 글자를 넣지 않는다.** `text: ""`, `textTop` 제거. 정체는
부호 태그로만 표시한다. 자식이 없는 단독 박스는 당연히 글자를 넣는다.

④ **점선 화살표 전면 금지. 전부 실선.** 분기는 선 스타일이 아니라 다이아몬드 옆 라벨로
구분한다(충족/미충족, 예/아니오). 라벨은 `noFrame: true` 글자 상자이고 태그를 붙이지 않는다.
**`noFrame`은 분기 라벨 전용**이며 결과 서술이나 패널 제목에는 금지다. 박스 테두리의
`dash: true`(컨테이너 점선)는 계속 허용한다.

**전수 검산 코드** (도면 세트 전체를 한 번에 돌린다)

```python
from collections import Counter
c = Counter(t['boxId'] for t in d['tags']); multi = {k:v for k,v in c.items() if v>1}   # 2항
dash  = [a['id'] for a in d['arrows'] if a.get('dash')]                                 # 4항
many  = [b['id'] for b in d['boxes'] if b.get('text','').count('\n') >= 2]              # 1항 후보
def inside(p,ch): return (ch is not p and ch['x']>=p['x'] and ch['y']>=p['y']
    and ch['x']+ch['w']<=p['x']+p['w'] and ch['y']+ch['h']<=p['y']+p['h'])
titled = [b['id'] for b in d['boxes'] if b.get('text','').strip()
          and any(inside(b,o) for o in d['boxes'])]                                     # 3항
```

네 목록 모두 공집합이어야 한다. `many`는 「객체명+값」 2줄을 걸러내려고 3줄 이상만 잡으므로
실물 판정이 필요하다. **fs 하한 검사와 `minfs` 계산은 `text.strip()`이 있는 박스만** 대상으로
한다(`text: ""` 컨테이너와 `shape: "image"`는 제외. 안 그러면 전부 FAIL로 잡힌다).

### 1.8 채움(hatch) 의미 코드

앱 툴바 `채움바꾸기` 순환은 흰칠 → 빗금 → 점무늬이고, `.pbd` 속성은 다음 세 가지다.

| 값 | 표현 |
|---|---|
| `"hatch": true` | 45° 빗금 |
| `"hatch": "dot"` | 점무늬(빗금보다 연해 글자가 잘 읽힌다. 글자가 긴 박스에 쓴다) |
| 속성 없음 | 흰칠 |

`hatch`를 주면 앱이 `dash`, `noFrame`을 지운다(겸용 불가).

회색 음영을 못 쓰는 흑백 도면에서 상태 대비를 표현하는 유일한 수단이므로, **세트 전체에
의미 코드를 고정**하고 이 스타일가이드에 적어 둔다. 예: 「빗금 = 확정, 충족, 정규화 완료 /
점무늬 = 후보, 보류, 미충족, 재검증」. 한 도면에 합쳐 3~4개 박스까지만 쓰고, 전체 조망
도면(시스템 블록도, 전체 흐름도)은 **채움 없이 깨끗하게** 둔다.

### 1.9 레이아웃 함정 4종 (실측)

1. **세로로 쌓은 박스를 한 점으로 모으면 반드시 관통한다.** 같은 x 열의 N개 박스를 아래 한
   박스로 팬인시키면 첫 박스에서 나온 선이 중간 박스들을 뚫는다. `bend`로 우회해도 결국
   어딘가를 지난다. **해법은 배치 변경뿐**이고, 팬인 대상을 **가로 3열로 재배치**하면 자동
   라우팅이 깔끔한 스파인을 만든다. 팬아웃(1 -> N)은 세로 배치가 정상 동작하지만
   팬인(N -> 1)은 가로 배치가 필요하다.
2. **★ 흐름도는 단계 박스 옆에 산출물 객체 박스를 세운다.** 절대 금지 2항 때문에 흐름도만
   그리면 그 단계가 만들어내는 객체 부호가 도면 어디에도 올라가지 못하고, 본문은 그 부호를
   서술하므로 정합성 점검에서 「본문에만 있는 부호」로 걸린다. 정석은 **세로 스파인에 단계
   박스를 쌓고, 각 단계 오른쪽에 그 단계의 산출물 객체 박스를 중심 y를 맞춰 세우는 것**이다
   (단계 -> 객체 가로 화살표 1개). 입력 객체는 왼쪽 열에 같은 방식으로 둔다. 단계 박스에는
   S부호만, 객체 박스에는 객체 부호만 달리므로 2항도 지켜진다. 가로로 넓어지므로 인쇄 검산을
   다시 돌린다(3열이면 폭 2600~2700px까지 늘어난다).
   - **행위 주체는 예외다.** 프로세서, 시스템 전체는 본문 도면 문단 첫 문장에 거의 항상
     나오지만 흐름도와 개념도에 박스로 그리지 않는다(블록도에만 둔다). 정합성 점검에서
     이 둘이 「본문에만 있음」으로 잡히면 오탐이므로 화이트리스트로 뺀다.
3. **도형은 의미를 말한다.** `cloud`는 통상 **"망"**을 뜻하므로 외부 시스템이라고 무조건 쓰면
   안 된다. 언어 모델처럼 시스템의 **통신 상대인 별개 객체는 직사각형**이 맞다. `cylinder`는
   저장 대상(DB, 그래프, 이력)에만 쓴다.
4. **도면은 처리 주체만 그리고 입력 데이터를 빼먹는다.** 블록도를 그리면 `~부` 같은 처리
   주체와 출력물만 박스가 되고, 입력측 데이터 객체는 화살표의 출발점으로만 취급되어 부호가
   붙지 않는다. 본문에 수십 회 등장하는 객체가 도면 전 세트에 없는 상태가 실제로 발생한다.
   청구항 구성요소가 미도시면 지원요건 시비가 붙으므로 §5 체크리스트의 차집합 검산으로 막는다.

## 4. 유형별 수정 프롬프트 템플릿 (복붙 후 값만 교체)

### 4.1 시스템 블록도 — 기능부 추가/명칭변경
```
도⟨N⟩에서 ⟨코어(예: 프로세서 900)⟩와 기능부들의 양방향 화살표는 유지하고,
⟨우측/좌측⟩ 열 ⟨위치⟩에 "⟨새 기능부명⟩"을 추가한다. 부호 ⟨新부호⟩,
크기 300×90 rect fs⟨24⟩, 코어와 양방향 ortho 2개로 연결. 외곽 컨테이너 h를 늘려 감싸고
태그는 바깥 dx=w+40에 배치.
```

### 4.2 흐름도 — 단계 삽입/분기 경로 변경
```
도⟨N⟩ 흐름에 "⟨새 단계⟩"를 ⟨앞단계⟩와 ⟨뒷단계⟩ 사이에 삽입한다. 600×70 rect fs⟨22⟩,
세로 스파인 중심 x 유지, 이후 단계 y를 118씩 밀어 간격 보존. 새 부호 ⟨S…⟩만 부여하고
기존 하위 부호가 밀리면 먼저 알릴 것(명세서 동시수정 대상).
```
```
도⟨N⟩ "⟨판단 diamond⟩" 분기의 ⟨No/Yes⟩ 경로 목적지를 "⟨현재⟩"에서 "⟨변경⟩"으로 바꾼다.
diamond 크기와 라벨(noFrame) 위치, 세로 스파인 정렬은 유지.
```

### 4.3 개념도 — 카드 추가/항목 교체
```
도⟨N⟩ ⟨카드명⟩을 ⟨M⟩개에서 ⟨M+1⟩개로 늘린다. 새 카드는 기존과 같은 ⟨375×350⟩ fs⟨16⟩,
항목 포맷 유지, 값은 "⟨항목1: … / 항목2: …⟩". 상하 컨테이너 w를 카드 전부 감싸게 넓히고
팬아웃/팬인 화살표를 ⟨M+1⟩등분으로 재정렬. 부호는 ⟨…⟩.
```

### 4.4 UI 예시도 — 요소 추가
```
도⟨N⟩ ⟨패널명⟩에 "⟨☐ 새 항목⟩"을 추가한다. 기존 요소와 같은 크기·fs⟨23⟩,
y를 ⟨52⟩씩 내려 정렬, 패널 h가 모자라면 늘린다. UI라 부호 태그는 부여하지 않는다.
```

### 4.5 화살표 정렬 교정 (전 유형 공통)
```
도⟨N⟩ 화살표가 박스를 관통하거나 계단 꺾임이 있는지 렌더로 확인하고,
상하 연결은 중심 x, 좌우 연결은 중심 y를 맞춰 교정한다. 양방향은 두 박스 중심축 정렬로
화살촉이 양쪽에 보이게. 부호 위치는 유지.
```

## 5. 수정 후 체크리스트 (렌더 육안검증)

1. 글자 잘림 없음(특히 fs16). 3줄 이상이면 h를 키운다.
2. 부호 태그가 화살표·테두리에 물리지 않음.
3. ortho 계단 꺾임 없음 → 상하=중심 x, 좌우=중심 y 정렬.
4. 팬아웃 스파인이 다른 박스 관통 안 함. 스파인 x=(소스 우변+타깃 좌변)/2.
5. 컨테이너가 내부 박스를 다 감쌈(여백 40px+).
6. **부호·단계명이 명세서 최신본 본문·【부호의 설명】과 일치.** 바꿨으면 명세서도 수정 대상으로 보고.
7. 양방향 화살표 화살촉이 양쪽에 보임(중심축 정렬).
8. **인쇄 검산 통과**: `fs x min(170/maxX, 255/maxY) >= 3.2mm`. `text.strip()`이 있는 박스만 대상.
9. **절대 금지 4항 전수 검산**(§1.7 코드)이 네 목록 모두 공집합.
10. **본문 -> 도면 고아 부호 0건.** 본문에서 부호가 붙은 객체를 전부 뽑아 도면 태그 집합과
    차집합을 낸다. 위험한 방향은 본문 -> 도면이다(도면에만 있는 태그는 자연히 잘 지켜진다).

    ```python
    body = set(re.findall(r'\((S?\d{3})\)', BODY))
    tags = {t['label'] for f in pbds for t in f['tags']}
    assert not (body - tags), body - tags      # 행위 주체(프로세서, 시스템)는 화이트리스트
    ```
11. **도면 라벨 문구를 본문 표기에 맞춘다.** 도면은 공간이 좁아 명사형("의미적 대응 판단"),
    본문은 동사형("의미적 대응을 판단하는 단계")으로 쓰기 쉬운데, 심사관과 번역자가 둘을
    대조하므로 **도면 쪽을 본문에 맞추는 것이 옳다**. 조사 하나 차이도 맞춘다.
12. 육안 검증은 3회로 안 끝난다. 13장 세트에서 **7회전**이 걸렸고 회전마다 잡힌 결함 유형이
    달랐다(z 은닉 -> 부호 잘림 -> 경로 관통 -> 폰트 규격 -> 재배치 후 신규 관통 -> 태그 여유 ->
    최종 미세). 중간 회전은 저해상도(scale 0.7~1.2)로 돌려도 결함은 그대로 보인다. 최종만 scale 3.

## 6. 산출·마무리

- 검토용 scale 2 → `PNG_out\도면N_검토.png`, 확인 후 출원용 scale 3 → `PNG_out\[도면NN]_이름.png`.
- 파일명 규약: `[도면0N]_설명_유형.png` (예 `[도면06]_값단위의미역할_3중검증_흐름도.png`).
