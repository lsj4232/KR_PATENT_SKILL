# 청구항 통합 체크리스트

청구항 초안과 발명자료를 대조한다. 문체 선호보다 기술적 의미와 근거가 우선한다.

- [ ] 각 구성·관계·수치의 원자료 위치를 확인했는가?
- [ ] 보호 대상과 카테고리가 사용자의 의도 및 기술적 실체에 맞는가?
- [ ] 방법의 주체·입력·처리·결과 또는 장치의 구조·결합·작동이 이어지는가?
- [ ] 자료에 없는 판단 단계·모델·하드웨어를 생성하지 않았는가?
- [ ] 동일 용어가 같은 대상을 뜻하며 선행 기재가 있는가?
- [ ] 종속항이 부모항의 한정을 유지하고 추가 한정을 갖는가?
- [ ] 인용 누락·순환·양립 불가능한 한정이 없는가?
- [ ] 다른 독립항은 실제 보호 목적과 설명 근거가 있는가?
- [ ] 글자 수·항 수·문장 패턴을 맞추기 위해 필요한 기술 내용을 빼거나 만들지 않았는가?
- [ ] 사용자에게 허용받은 기존 청구항의 변경 범위를 지켰는가?
- [ ] 출원 후 수정이면 최초 명세서·도면의 근거와 보정 가능 범위를 확인했는가?

본문·도면에는 확정 청구항 버전, 용어표, 부호 대응, 미확인 사실을 인계한다. 프로세서가 수행하는 기능을 실제 독립 하드웨어인 것처럼 바꾸지 않는다. 설계 해설·검토 주석은 청구항 문언 밖에 둔다.
