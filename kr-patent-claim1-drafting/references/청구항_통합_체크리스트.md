# 청구항 통합 체크리스트 (설계 + 형식)

청구항 초안 완성 후 확인한다. 설계 항목이 형식 항목보다 우선한다.
`kr-patent-claim1-drafting`(독립항)과 `kr-patent-dependent-claim-drafting`(청구항 2~N)이
공유하는 최종 게이트다.

## 1. 설계

- [ ] 방법항을 먼저 작성했는가
- [ ] 핵심 단계를 하나(최대 둘)로 특정했는가
- [ ] 핵심 단계 외의 단계를 포괄적으로 기재했는가
- [ ] 시스템항에 「~부」 형태의 기능부 나열이 없는가
- [ ] 시스템항이 메모리·프로세서 구조로 되어 있는가
- [ ] 메모리에 저장되는 데이터가 특정되어 있는가
- [ ] 모든 단계가 입력 → 처리 → 출력으로 환원되는가
- [ ] 「결정」·「판단」 단계에 데이터 처리 근거가 있는가
- [ ] 함께 산출되는 데이터가 하나의 단계로 묶여 있는가
- [ ] 역방향 처리의 대상이 「관계」로 특정되어 있는가
- [ ] 최종 단계가 분기 구조로 되어 있는가
- [ ] 프로그램항이 인용 형식이 아닌 독립 기재인가
- [ ] 각 독립항의 관점·어휘·범위가 서로 다른가
- [ ] 제1독립항이 상세하고 나머지가 더 넓은가
- [ ] 포인트 주석이 부착되어 있는가

## 2. 형식

- [ ] 나열식·선택적 표현이 없는가
- [ ] 부정 표현이 없는가 (않도록·않고·아닌·없이)
- [ ] 금지 어휘가 없는가 (또는·선택적으로·크게·향상·~하기 위하여)
- [ ] 알고리즘 명칭 직접 한정이 없는가 (「기 학습된 모델」 등으로 일반화)
- [ ] 상위 개념으로 종결했는가 (적용 대상 한정 명칭 없음)
- [ ] 핵심 데이터 파이프라인이 입력 → 변환 → 분기 → 종합 → 출력으로 드러나는가
- [ ] 마지막 단계 세미콜론 제거, 직전 단계 `; 및`을 적용했는가
- [ ] 선행 기재/`상기` 규칙을 준수했는가
- [ ] 정보 용어가 최초 등장 시 관형절로 정의되어 있는가
- [ ] 정보를 능동 행위 주체로 표현하지 않았는가
- [ ] 각 종속항이 3줄을 넘지 않는가
- [ ] 정량 수치가 청구항에 포함되어 있지 않은가
- [ ] 용어 앵커링 표와 동작 주체가 확정되어 있는가

## 3. 명세서·도면 연동 (청구항 확정 직후 인계 사항)

청구항이 프로세서 기반으로 작성되면 명세서와 도면도 이에 맞춘다.

- **도면** — 시스템 블록도는 메모리·프로세서·통신부를 실제 구성으로 두고, 기능 단위는
  프로세서 내부의 **점선 영역**으로 표현한다.
- **본문** — 기능 블록을 설명하되, 그것이 프로세서가 수행하는 처리를 **기능적으로 구분한
  것**임을 명시한다. 독립된 하드웨어 구성인 것처럼 서술하지 않는다.
- **부재번호** — 데이터 처리 흐름상 실제로 산출·변환되는 객체 단위로 부여하고, 직접 산출
  객체와 후속 처리 객체를 구분한다.
- **용어** — 청구항 용어를 변경하거나 동의어로 치환하지 않는다.

인계 대상 스킬: `kr-patent-symbol-design`(부호 체계), `kr-patent-spec-drafting`(본문),
`patent-block-diagram`(블록도 작도), `kr-patent-consistency-check`(최종 정합성).
